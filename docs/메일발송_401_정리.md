# 인증 메일이 나가지 않는다 — NCP 401 Authentication Failed

2026-09-28 기준. **미해결.** 운영에서 회원가입 중 이메일 인증번호를 받으려 하면 실패한다.

---

## 1. 증상

가입 화면에서 이메일을 넣고 「인증번호 받기」를 누르면:

> 가입하지 못했습니다
> 인증 메일을 보내지 못했습니다. 잠시 후 다시 시도해 주세요.

브라우저 콘솔:

```
api.hanseongge.com/api/v1/auth/email/verification:1  Failed to load resource: 502
```

> ⚠️ **이 502 는 원인을 구분하지 못한다.** 키가 틀려도, 발신 주소가 안 맞아도, 서비스 신청이 안 됐어도
> 전부 같은 `MAIL_SEND_FAILED` 502 로 나온다 (`ErrorCode.java:150`). 화면만 보고 판단하면 안 되고
> **반드시 서버 로그를 봐야 한다.**

참고로 같이 찍히는 `/auth/refresh` 401 은 정상이다 — 로그인하지 않은 상태라서 그렇다. 무관하다.

## 4. 엔드포인트는 살아 있다

콘솔 메뉴에서 Cloud Outbound Mailer 가 안 보여 "제품이 없어진 것 아니냐"는 의심이 있었으나,
**게이트웨이 응답이 아니라고 말한다.**

```bash
curl -s https://mail.apigw.ntruss.com/api/v1/mails
{"error":{"errorCode":"300","message":"Not Found Exception","details":"URL not found."}}

curl -s -X POST https://mail.apigw.ntruss.com/api/v1/mails
{"error":{"errorCode":"200","message":"Authentication Failed",
          "details":"Authentication information are missing."}}   ← 401
```

읽는 법:

- `GET` 은 404 — 그 경로에 GET 메서드가 없을 뿐이다. **제품 유무와 무관하다**
- `POST` 는 401 — **경로가 살아 있고 인증 단계까지 도달한다.** 없어진 주소는 404 를 주지 인증 실패를 주지 않는다
- 헤더 없이 부르면 `missing`, 우리 앱은 `invalid` — 즉 **우리는 헤더를 제대로 보내고 있고 NCP 가 그 값을 거부한다**

공식 문서도 같다:

- SENS API 문서에는 **메일 API 가 없다** (SMS·알림톡·브랜드 메시지 셋뿐)
- Cloud Outbound Mailer API 문서는 살아 있고 `POST /api/v1/mails` 그대로다
- **serviceId 를 받지 않는다.** serviceId 는 SENS 의 SMS·Biz Message 쪽 개념이다

콘솔 메뉴가 개편되어 안 보이는 것과 API 가 없어진 것은 다른 이야기다.

## 5. 우리 구현은 문서와 일치한다

`NcpApiSigner.sign()` — [`NcpApiSigner.java:24-29`](../backend/src/main/java/com/hanseongge/domain/notification/NcpApiSigner.java)

```
StringToSign = "POST /api/v1/mails\n" + timestamp + "\n" + accessKey
signature    = Base64(HmacSHA256(secretKey, StringToSign))
```

헤더 4종 — `Content-Type`, `x-ncp-apigw-timestamp`, `x-ncp-iam-access-key`, `x-ncp-apigw-signature-v2`.
NCP 문서 예시와 같다. **코드를 고칠 이유가 없다.**

## 6. 남은 가설 둘

`errorCode 200 / Invalid authentication information` 은 API Gateway 가 내는 것이고, 남은 원인은 값뿐이다.

### (가) 액세스 키와 시크릿 키가 짝이 아니다

인증키가 두 벌 있으면 A의 액세스와 B의 시크릿을 섞기 쉽다. 또는 시크릿을 「보기」로 펼치지 않고
가려진 상태(`****`)를 복사한 경우.

### (나) 서브 계정(Sub Account) 키의 제한에 걸린다

현재 키가 `ncp_iam_` 으로 시작한다 — IAM/서브 계정 키 형식이다.
NCP 문서의 포털 계정 키 예시는 접두사 없는 40자(`6uxz1nKkcYwUjWRG5Q1V7NsW0i5jErlu2NjBXXgy`)다.

서브 계정 키는 두 가지 제한을 받고, **둘 중 하나만 어긋나도 같은 401 이 난다.**

| 제한 | 확인할 곳 |
|---|---|
| 서비스 권한(정책) | Sub Account > 해당 계정 > 권한에 메일 발송 권한이 있는지 |
| API Access Source (허용 IP/VPC) | 서버 공인 IP 가 등록돼 있는지 (`curl -s ifconfig.me`) |

## 7. 다음에 할 것

### 7-1. 키가 아예 못 쓰는 것인지, 메일 권한만 없는 것인지 가른다

같은 키로 SENS 를 찔러 본다. SENS 프로젝트(`hanseongge`)가 이미 있으므로 권한이 있으면 목록이 나온다.

```bash
sudo bash -c '. /etc/hanseongge/api.env
T=$(($(date +%s)000)); U=/common/v2/projects
S=$(printf "GET %s\n%s\n%s" $U $T $APP_MAIL_ACCESS_KEY|openssl dgst -sha256 -hmac $APP_MAIL_SECRET_KEY -binary|base64)
curl -s -w "\n%{http_code}\n" https://sens.apigw.ntruss.com$U -H "x-ncp-apigw-timestamp: $T" -H "x-ncp-iam-access-key: $APP_MAIL_ACCESS_KEY" -H "x-ncp-apigw-signature-v2: $S"'
```

- **200** → 키는 유효하다. 메일 권한·구독 문제 (가설 나)
- **401** → 키 자체가 틀렸거나 제한된 키다 (가설 가)

### 7-2. 어느 쪽이든 — 계정 인증키로 교체

**마이페이지 > 인증키 관리**(https://www.ncloud.com/mypage/manage/authkey)에서 신규 발급.
계정 인증키는 권한·IP 제한을 받지 않아 두 갈래를 한 번에 덮는다.

1. 신규 API 인증키 생성
2. **같은 행**에서 액세스 키 / 시크릿 키(「보기」 클릭 후 전체) 복사
3. `/etc/hanseongge/api.env` 갱신
4. `sudo systemctl restart hanseongge-api`
5. 아래 7-3 으로 확인
6. 되면 **옛 키 삭제**

### 7-3. 확인은 가입 화면 말고 이걸로

가입 흐름으로 확인하면 **가입 토큰 15분**(`OAUTH_SIGNUP_TTL_MINUTES`)이 계속 만료돼 번거롭다.
키만 바로 시험한다 (메일은 나가지 않는다).

```bash
sudo bash -c '. /etc/hanseongge/api.env
T=$(($(date +%s)000))
S=$(printf "GET /api/v1/mails\n%s\n%s" $T $APP_MAIL_ACCESS_KEY|openssl dgst -sha256 -hmac $APP_MAIL_SECRET_KEY -binary|base64)
curl -so /dev/null -w "%{http_code}\n" https://mail.apigw.ntruss.com/api/v1/mails -H "x-ncp-apigw-timestamp: $T" -H "x-ncp-iam-access-key: $APP_MAIL_ACCESS_KEY" -H "x-ncp-apigw-signature-v2: $S"'
```

**401 이 아닌 숫자**면 인증 통과다.
