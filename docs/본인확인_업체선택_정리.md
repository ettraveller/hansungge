### 회원가입 구조 (2026-09-19 개편, 이미 구현·배포됨)

- **로그인 ID = 휴대폰번호.** 로그인 수단: 휴대폰+비밀번호 / 문자 인증번호 / 구글·네이버·카카오 소셜
- **모든 가입에 휴대폰 본인확인 필수** (자체 가입, 소셜 가입 모두)
  - 가입 순서: 약관 동의 → 본인확인 → 비밀번호(+선택 이메일) → 계정 생성
  - 비밀번호 찾기도 본인확인으로 한다
- **같은 사람 판정은 DI 로 한다.** DB 에 "탈퇴하지 않은 회원은 DI·이름·생년월일 필수" 제약이 있다
  - 휴대폰번호로 판정하지 않는 이유: 번호는 해지 후 다른 사람에게 재할당된다. 번호로 판정하면
    번호를 물려받은 사람이 앞사람 계정(정산계좌 포함)으로 들어간다
  - 같은 DI 로 다시 가입하면 새 계정을 만들지 않고 기존 계정으로 안내한다
- **CI 는 저장하지 않는다** (정보통신망법 §23조의5·6 — 목적 외 사용 처벌이 무겁다)
- 본인확인 업체는 인터페이스로 분리돼 있어 **업체 연동 부분만 갈아 끼우면** 가입 화면·흐름은 그대로 쓴다

**즉, 어떤 본인확인 서비스든 조건은 "DI 를 준다" 하나다.**

## 4. 핵심 질문과 현재 판단

**질문: PASS 로 회원가입(본인확인)을 할 수 있나?**

| 방법 | PASS 로 가입 | DI | 판단 |
|---|---|---|---|
| 이니시스 통합인증 **본인확인** | ✗ (은행·토스·금융인증서만) | ○ | 은행 앱·토스가 없는 고객은 가입 불가 |
| 이니시스 통합인증 **간편인증** | ○ | ✗ | 같은 사람 판정을 이름·생년월일·번호로 해야 함 → 번호 재할당 사고 위험. 상품 스스로 "회원가입용 아님"으로 구분. **비추천** |
| **휴대폰 본인확인 서비스** (통신사 PASS/SMS) | ○ | ○ (통상 제공 — 업체별 확인 필요) | 휴대폰만 있으면 누구나. 대부분 쇼핑몰이 쓰는 방식. **추천** |

- "휴대폰 본인확인 서비스"는 이니시스 통합인증과 **별개 상품**이다. 알려진 제공 업체: KG모빌리언스(같은 KG그룹), NICE평가정보(나이스아이디), 드림시큐리티 등
  — 이 목록과 각 업체의 DI 제공 여부·단가는 **확인되지 않은 일반 지식**이다. 견적으로 확인할 것
- 휴대폰 본인확인으로 가면 해당 업체 연동을 새로 붙여야 한다 (가입 화면·흐름·DB 는 그대로)
- 이미 만든 이니시스 본인확인은 버리지 않고 "은행 앱으로도 인증" 선택지로 나중에 같이 붙일 수 있다

**현재 추천: 휴대폰 본인확인 서비스를 주력으로.** 중장년 고객층에서 은행 앱·토스 인증서 보유율이 PASS 보다 낮을 것이라는 판단.
